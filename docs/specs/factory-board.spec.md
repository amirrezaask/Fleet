title: "Factory task board"

## Area

The single shared `skills/factory/assets/task-board/` package (`amirreza-factory`,
run with `npx amirreza-factory`) and Factory's usage instructions.

## Requirements

- **R1:** Given Node.js 24+, when running `amirreza-factory [dir...]`, then one server starts for all projects: listed directories are registered in `$FACTORY_HOME/projects.json` (default `~/.agents/factory`), an empty registry adopts the cwd when it has a task store and no project receives a copy of the server, UI, fonts or a package script.
- **R2:** Given the running server, when opening its reported URL, then it binds only to 127.0.0.1 on PORT or, by default, any free port the OS assigns (reported at startup), reads each registered project's task store `$FACTORY_HOME/<main checkout path relative to home>/`, so a worktree shows the same tasks as its main checkout (amended 2026-11-09 by ADMIN's central-store request), reads task directories `<store>/<task>/` (subtasks in `<task>/subtasks/<subtask>/`) whose TASK.md `status:` key (or legacy TASK.html `status` meta tag) is `backlog`, `inprogress`, `blocked` or `done` (missing or unknown reads as `backlog`), and displays Backlog, In progress, Blocked, and Done columns with titles and counts. A parent card shows done/total subtask counts for all descendants found in nested `<subtask>-<status>/` directories (and legacy `subtasks/<status>/` trees). Moving a card renames the directory to the new status; a legacy task migrates to the flat layout (amended 2026-11-02, flat task layout and `.factory/` root).
- **R3:** Given a task with valid metadata (YAML frontmatter in TASK.md, or meta tags in a legacy TASK.html), when opening its card, then a modal displays its title, status chip, updated date, optional stage, and Intent/Design/Plan/Debrief document navigation (Intent falls back to a legacy BRIEF; a missing Design or Debrief shows "Not written yet") (amended 2026-11-02 by ADMIN's factory-sdlc-pipeline request) with rendered, sanitized Markdown or legacy HTML (Markdown wins when both exist; amended 2026-11-03 by ADMIN's Markdown-documents request) using controlled shadcn/Radix Dialog and Tabs components. Close and Escape return to the board. Missing or unreadable documents show an unavailable state. The modal is 80vw wide and 90dvh tall, with the document scrolling inside the fixed header and tabs.
- **R4:** Given a drag/drop or keyboard move with a valid token, origin, task, and supported status, when submitted, then the server writes the new status into the task's TASK file (the `status:` frontmatter key of TASK.md, or in a legacy TASK.html the `status` meta tag, added after `updated` when absent) and bumps `updated` without renaming or moving any directory, preserves other metadata/body content, subtasks and both brief/plan files, and returns the updated task as JSON so React updates card placement and column counts without navigating. The legacy /status form endpoint remains available.
- **R5:** Given metadata or file edits made outside the board, when reloading the browser, then the board rereads the current task documents. Invalid tasks and directories under the task root whose names are not valid task names produce visible errors while valid tasks remain available; empty columns display an empty state.
- **R6:** Given invalid names/statuses, foreign-origin or tokenless writes, or symlinked task paths/documents, when requested, then the server rejects mutations and does not write outside real task document paths. Rendered documents cannot introduce executable HTML or script URLs.
- **R7:** Given a board status update, when it succeeds, then no agent session, workflow execution, approval, verification, task document edit, task creation/deletion, or Codex/Claude integration is performed. Status is bookkeeping only.
- **R8:** Given the skill package, when using it, then the optional local board uses React, adapted inline shadcn source, and Tailwind without a database or separate build command; installed local dependencies prepare assets once at server startup. Other workflow automation and evaluation tooling is outside Factory's current scope.

- **R9:** Given a board page, when rendering, then only the consuming project name appears above the columns; no Factory banner, tagline, or Refresh button appears. The name comes from package.json displayName, then name, then the project directory, and is HTML-escaped.
- **R10:** Given the board assets, when rendering, then project/document headings use bundled Anthropic Serif and controls use bundled Anthropic Sans, served from the local origin with warm neutral styling. Font loading requires no external request.

- **R11:** Given pointer interaction or an opened task modal, when motion is allowed, then controls/cards have brief color transitions and the modal enters with a short fade and 6px translation. When prefers-reduced-motion is reduce, these animations and transitions are disabled. The board uses Claude-reference cream/neutral/clay colors and dark primary controls.

- **R12:** Given a task card, when dragged into another status column or moved through its pointer/touch grip, then the target column is highlighted and a successful status write updates React state in place. The selector and submit button are absent. Clicking the title still opens task documents.
- **R13:** Given focus on a card or grip, when Space/Enter picks up the card, Left/Right chooses a column, and Enter confirms, then the same status operation runs; Escape cancels without a write. Announcements expose move state, and rejected requests display an error and release busy/drag state.

- **R14:** Given index.html beside server.ts, when starting the server, then the embedded typed React/shadcn application and Tailwind theme are prepared locally into in-memory app.js/app.css responses. Application UI source stays in one HTML file; fonts and runtime assets require no CDN.
- **R15:** Given an already loaded board, when opening/closing a task, switching document tabs, or moving status, then no full-page navigation or reload occurs. Opening a task fetches its sanitized documents once, tab selection stays in local state, and card moves preserve the mounted app. Failed operations release busy state and expose recovery guidance.

- **R16:** Given no registered project, when loading the board, then it shows an empty board with guidance to add a project directory.

- **R17:** Given a task with nested subtask directories, when its modal is open, then a Subtasks rail beside the document (viewport at least 1024px, otherwise a Subtasks tab) lists each direct subtask with status and descendant counts. Selecting one loads that subtask's Brief, Plan and own Subtasks in the same modal to any depth, with a Back button and a breadcrumb of ancestors to return, and focus moves to the title. Subtask documents are served at `/api/tasks/<parent>/<child>/...`; status moves stay top-level only.

- **R18:** Given the board header, when adding a directory path (token and origin checked), choosing a project in the selector, or pressing Stop watching, then the registry updates, the selection is remembered in the browser, and every task, document and status request is scoped by `project` id. File changes in any registered project stream an SSE change event naming the project; the UI reloads only for the selected one. Unknown project ids return 404.

- **R19:** Given the header project menu, when choosing "Add project…" (or "Choose folder…" on the empty state), then the server opens the host's native folder chooser (`osascript` on macOS, `zenity` then `kdialog` on Linux), registers the chosen directory and switches to it. The request needs the board token, only one dialog may be open at a time (409 otherwise), Cancel or a closed tab kills the dialog and is not an error, and an unsupported host reports so and the UI falls back to the "Enter a path" input. Removing a project asks for inline confirmation and never touches files on disk.
- **R20:** Given the board, when rendering, then light and dark palettes follow `prefers-color-scheme` unless the header toggle (System/Light/Dark, remembered in localStorage) overrides it; `/theme.js` applies a remembered choice before first paint, and all surfaces, shadows and overlays use theme tokens. The header is sticky, the modal is capped at 1100px (full screen below 768px), and switching project dims the previous board instead of resetting it.

- **R21:** Given the Board view, when a column header is dragged with a mouse, its grip is dragged by touch, or its grip is lifted with Space or Enter and moved with Left/Right, then the columns preview the new order live; dropping or Enter keeps it and Escape restores the previous order. The order is remembered in the browser (`factory-columns`), an entry that does not name every status exactly once falls back to Backlog, In progress, Blocked, Done, a Reset columns control appears while the order differs from that default, and card keyboard moves walk the columns in their on-screen order. Reordering writes nothing to task files.
- **R22:** Given a loaded project, when choosing a view from the header or pressing 1 to 7, then the same tasks render as Board, Pipeline (a row per task on the Intent, Design, Plan, Build, Review, Done stations), Focus (blocked, in progress, next and recently done, with status actions), Hill (uphill Intent to Plan, downhill Build to Done), Timeline (created to last update, with a dotted tail while open), Table (sortable, with an inline status control) or Portfolio (every registered project). The choice is remembered in the browser (`factory-view`). A task whose status is done reads as stage Done in every view, and a task with no recorded stage is shown as such rather than given one.
- **R23:** Given any view, when typing in the header filter (focused with `/`), then tasks are narrowed by id, title, status or stage without a request. Hide done (Pipeline, Hill, Timeline, Table) is remembered in the browser. Status actions outside the Board use the R4 status write and its failure handling. Portfolio reads each project through `/api/board`, refreshes on a change event from any registered project, and an unreadable project is reported on its own row while the others remain.
