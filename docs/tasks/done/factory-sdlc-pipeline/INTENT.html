Factory follows the AI-native SDLC pipeline

Intent · Approved · created 2026-11-02 16:40 · Claude Code claude-opus-5-5

Problem

Factory runs clarify → plan → build → verify, and loads whenever an agent does software work. ADMIN wants the pipeline from Claude's AI-native SDLC playbook, started only on request, with documents sized to whoever reads them.

Outcome

Factory runs Intent → Design → Plan → Build → Test, only through /factory and its stage commands. Each stage produces an HTML document from a template.

Requirements

IDRequirementAccepted when
R1The article's knowledge, tips and tricks are extracted, and ADMIN's reading of the pipeline is compared with the article's.An HTML page in this task's design/ covers every stage, the principles and the differences.
R2Factory's stages are Intent, Design, Plan, Build and Test, with the artifacts ADMIN described: intent ≈ brief; design = AI-made artifacts; plan = agent plan with the tests decided up front; build = debrief only; test = cheap tests during build, heavy tests only in Test.The skill and its stage guides describe these stages, artifacts and gates.
R3Factory is opt-in and runs only through /factory or the stage commands.Every Factory skill disables implicit invocation, and AGENTS.md no longer requires Factory for all software work.
R4The templates follow the new format. They are still HTML with the Factory style, short for human readers and detailed for agent readers.Intent, design, plan, debrief, test report and task templates exist with the shared tokens.
R5Existing tooling and legacy tasks keep working.The board and installer handle the new documents and still read legacy BRIEF files. npm test, the type check and the skill check pass.

Boundaries

  • Non-goals: migrating existing tasks; deploy or production automation; hooks that enforce the policies.
  • Constraints: HTML artifacts and the Factory tokens; TypeScript tooling; the skill entrypoint stays under 150 lines.
  • Preserved: task status directories, subtasks, the board's safety rules (docs/specs/factory-board.spec.md), and Atlas ownership.
  • Design: needed. Command names, gates and the scope of each document were open.

Open questions

  • ADMIN invited questions, but this session runs autonomously, so the agent decided them and listed each decision in DESIGN.html for review.
