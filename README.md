# Amirreza's Custom Agents.md

`AGENTS.md` holds global conventions. `~/.agents` is the agent memory vault: an
Obsidian vault and Git repository that every agent reads and writes, holding
memories and each project's Factory tasks. Factory is an opt-in delivery pipeline,
Intent → Design → Plan → Build → Review, started only by `/factory` or a stage
command. Every document agents write is Markdown; ADMIN reviews any of them rendered
as Claude-styled HTML with `md <file.md>`.

## Skills

| Skill | Task trigger |
| --- | --- |
| `agentic-memory` | Any task: read and write the shared memory, `recall` from the vault |
| `factory` | Only `/factory`: route a task through the pipeline, stopping at human gates |
| `change-review` | An explicit review request: code, security, UI and UX reviewers, verdict first |
| `debugging` | A defect whose cause is not yet proven: reproduce, find the cause, failing test, fix |
| `maintenance` | Looped review-and-fix subagents per area until two rounds find nothing |
| `performance` | Systems, browser, and GPU performance investigations and optimization |
| `configure-oxlint` | Base Oxlint/Oxfmt policy and upstream anti-slop skill installation |
| `resource-bounded-runs` | Large copies and resource-heavy build or test processes |
| `anthropic-design` | Claude-style or Anthropic-style UI: rules, tokens, component specs, web and Rust GPUI examples |

The catalog holds how we work, not what a library does: each skill is a procedure a
session follows for one kind of task. Rules that apply to every task belong in
`AGENTS.md`; project-specific procedures belong in that project's own skill folder;
library and framework knowledge is installed from its upstream (`npx skills add`) and
never edited in place.

## Factory pipeline

Adapted from the [AI-native SDLC playbook](https://claude.com/resources/articles/the-ai-native-sdlc-playbook):
every stage commits one artifact that the next stage reads, and the user's attention
goes to the gates.

| Stage | Command | Artifact | Reader | Gate |
| --- | --- | --- | --- | --- |
| Intent | `/factory intent` | `INTENT.md` | The user, one screen | The user approves |
| Design | `/factory design` | `DESIGN.md` + `design/` mocks and diagrams | The user reviews | The user accepts (or skip recorded) |
| Plan | `/factory plan` | `PLAN.md` with a fast/heavy test plan | Agents, verbose | Self-check, committed before code |
| Build | `/factory build` | Code, tests, `DEBRIEF.md`, `REVIEW.md` | Future agents; the user reads the verdict | Fast tests green, regression, acceptance, then heavy gates last |
| Review | `/factory review` | Review section of `REVIEW.md` | The user, verdict first | Four parallel reviewers (code, security, UI, UX) pass |

Factory uses `disable-model-invocation: true` (Claude Code) and
`agents/openai.yaml` `allow_implicit_invocation: false` (Codex), so hosts never load
it implicitly. Stage commands are thin entrypoints; the [Factory skill](skills/factory/SKILL.md)
holds the shared contract and `skills/factory/references/<stage>.md` holds each stage's
method. Tasks live in `~/.agents/projects/<project>/tasks/<task>/`. A task has no
`TASK.md` or other metadata file: its stage is the latest stage document it holds, and
it is done when `REVIEW.md` records `**Review verdict:** PASS`. There is no board.

## Agent memory vault

```text
~/.agents/
  memory/                                # the one shared memory, Claude Code's auto-memory format
    MEMORY.md                            # index: one line per memory
    <memory-name>.md                     # one fact per file
  projects/<project>/                    # <project> = checkout path relative to home, e.g. dev/GameBox
    TASKS.md                             # generated by tasks-index: one line per task
    backlog.md                           # requests waiting for `/factory next`
  projects/<project>/tasks/<NNN>-<name>/ # one Factory task; 001, 002, ... in creation order
    INTENT.md DESIGN.md design/ PLAN.md DEBRIEF.md REVIEW.md
    evidence/                            # raw output, gitignored
    subtasks/<NNN>-<name>/               # same files
```

ADMIN browses tasks, links and history in Obsidian. The
[agentic-memory skill](skills/agentic-memory/SKILL.md) holds the memory conventions;
the [Factory skill](skills/factory/SKILL.md) holds the task layout and the
templates. Plain files mean any agent with file access uses the vault; Git is the
backup. `recall <keywords> [--all]` (`tools/recall.ts`) prints the matching bullets and
paragraphs of every memory and the current project's `TASKS.md`, best first; `tasks-index [project]` (`tools/tasks-index.ts`) regenerates
`TASKS.md` from the documents each task holds (stage, title, links). `obsidian [dir]` (`tools/obsidian.ts`, linked onto PATH as
`~/.local/bin/obsidian`) opens a directory, default the current one, as a vault on
macOS; a folder Obsidian has not registered yet makes it restart once. The installer seeds the vault's `.gitignore`, Obsidian settings and memory
index once and never overwrites them. It also sets Claude Code's `autoMemoryDirectory`
to `~/.agents/memory` and turns each empty `~/.claude/projects/*/memory` folder into a
link to it, so Claude's auto-memory is the vault's memory.

## Markdown documents and `md`

Specs, intents, designs, plans, debriefs and reports are Markdown (see `AGENTS.md`),
so agents read and edit them cheaply and Git diffs stay readable. To review one:

```sh
md ~/.agents/projects/<project>/tasks/<task>/PLAN.md
md docs/areas/identity.md --out /tmp/review --no-open
```

`tools/md.ts` renders the file with the Claude tokens and bundled Anthropic fonts in
light and dark mode, shows frontmatter as chips, renders Mermaid code blocks, and also
renders the local Markdown files it links to so links work in the browser. Pages are
written to the system temp directory (`md-preview/`) and opened with the default
browser. The installer links it onto PATH as `~/.local/bin/md`.

## Install

Requires Node.js 24 or newer.

```sh
npm ci
npm run install:agents -- --dry-run
npm run install:agents
```

The installer links `AGENTS.md` into `~/.agents`,
`~/.codex`, and `~/.claude`. Each skill links separately into those hosts' skills
folders and Cursor's `~/.cursor/skills-cursor/`. It never replaces the whole
skills directory. Edits propagate through symlinks; rerun after catalog changes.

It also sets `autoCompactWindow` to 300000 in `~/.claude/settings.json` when it is
unset, so Claude sessions compact themselves at about 300K tokens, guided by the
Compact Instructions section of `AGENTS.md` (other settings are left untouched;
unparseable settings abort the install). A rerun removes the retired
`session-budget-hook.ts` entries and its `~/.claude/hooks/` link.

```sh
npm run install:agents -- --list
npm run install:agents -- performance
```

Selected installs include `agentic-memory`, `factory`, `change-review` and the global files.
Templates live in `skills/factory/templates/`. Installing through `npx skills`
includes bundled resources; `md`, `obsidian`, `recall`, `tasks-index`, AGENTS.md and the vault seed require this installer.

Managed `*_TEMPLATE.md` and `*_TEMPLATE.html` aliases in the global directories, and
the retired Factory board's `~/.local/bin/production-line` link, are removed even
when dangling. Managed communication, specification, atlas, hbs and `factory-<stage>` skill
links are removed on full and selected installs. Other retired skill links are cleaned only on a full
install. Known skill links from `~/dev/Amirreza.md` also migrate. Unrelated files,
directories, and symlinks are preserved; collisions fail preflight before changes.

## Maintain

`configure-oxlint` contains instructions only. Use
`npx skills add dmmulroy/anti-slop --skill install-anti-slop` for setup in other
projects. This repository's lint command uses the pinned upstream archive from
the lockfile, enabling generic and Effect rules.

Keep one skill per directory with matching metadata. Essential instructions stay
in `SKILL.md`; conditional details belong in linked references. Templates have
one canonical location.

```sh
npm test
npm run lint
npm run check:types
npm run check:skills
```

Tests use isolated temporary data and remove it afterward. Catalog validation
checks metadata, entrypoint size, scope wording, and local links; it does not
prove model routing or semantic adherence to the workflow.
